CONTEXT FOR THE LLM HELPING ME (leave this part as-is)

This is a local Flask web app ("Process Log", version 2) that students use
to log their study process and LLM use. Its internals live in an `app/`
subfolder that students aren't meant to need to open. Everything is saved
as plain JSON files in `logs/`, one file per log, named
<first-tag>_<YYYYMMDD-HHMM>.json. Nothing is sent over a network.

It is launched by running app/start.py. The easiest way is opening the
project folder in VS Code and pressing Run on app/start.py. Alternatives:
double-click Start.vbs (Windows, no console window), start.command
(macOS, double-click; first time needs right-click > Open because the file
came from a download), or app\start.bat (Windows, visible console, good for
debugging). start.py uses only the Python standard library and:
  1. Creates a Python virtual environment (app/venv/) if it doesn't exist
     (or rebuilds it if it was copied from another computer and won't run)
  2. Installs Flask into it (needs internet the first time only)
  3. Picks a free port (tries 5173 first, never 5000) and runs app/app.py,
     a Flask server on http://127.0.0.1:<port>
  4. Opens that URL in the default browser

Known issues to check first:
  - Requires Python 3.9+ installed ("python --version" or "python3
    --version" should work in a terminal). On a Mac, install the macOS
    installer from python.org. Do NOT accept a prompt to install Xcode
    command line tools just for this; python.org Python is enough.
  - On a Mac, start.command downloaded in a zip may be blocked by
    Gatekeeper or lack its executable bit. Right-click > Open fixes the
    first; otherwise run app/start.py from VS Code or a terminal
    ("python3 app/start.py").
  - Start.vbs needs pythonw.exe next to python.exe (present with a
    standard python.org install); if something goes wrong it logs to
    app/launch_log.txt, and also falls back to a visible window.
  - If a launch fails with "could not install Flask", check internet and
    run it again.
  - Nothing is installed system-wide. Deleting the app/venv folder and
    re-running the launcher is a safe way to reset if setup seems broken.
    Never delete logs/ - that is the student's data.
  - Logs are append-only by design; the app never edits or deletes an
    existing entry.
